# PA

Use this reference when extracting PA system requirements from a technical rider.

The primary goal is to determine what PA system must be provided locally and whether the rider specifies preferred systems, minimum performance requirements, or required system components.

## Extract

Identify requirements for:

- Main PA
- Subwoofers
- Front Fills
- Out Fills
- Delay Speakers
- System Processing
- System Engineer / PA Technician
- Rigging or deployment requirements
- Coverage requirements
- SPL requirements

For each item, preserve when available:

- quantity
- manufacturer
- model / series
- configuration
- performance requirement
- notes
- supply responsibility

## Supply Responsibility

Determine who must provide the PA system or related components.

Normalize to:

- `Artist Supplied`
- `Local Production`
- `Venue Supplied`
- `Unspecified`

Do not assume the PA is locally supplied unless the rider indicates this.

## Main PA

Capture:

- preferred manufacturer
- preferred system
- acceptable alternatives
- minimum system size when explicitly stated
- flown / ground-stacked requirements
- stereo / mono requirements
- coverage requirements

Examples:

- `L-Acoustics K2 preferred`
- `d&b J-Series acceptable`
- `Professional 3-way line array system`
- `System must provide even coverage throughout the audience area`

Do not infer an equivalent system unless explicitly asked to evaluate alternatives.

## Subwoofers

Capture:

- quantity when specified
- manufacturer
- model
- configuration
- cardioid / end-fire / array requirements
- flown / ground-stacked requirements
- notes

Do not infer subwoofer quantity from the main PA specification.

## Fills and Delays

Capture separately:

- Front Fills
- Out Fills
- Side Fills when part of the PA system
- Delay Speakers

Preserve placement or coverage requirements when stated.

## SPL and Coverage

Capture explicit requirements such as:

- target SPL
- maximum SPL
- dBA / dBC weighting
- measurement position
- coverage angle
- frequency response
- audience-area coverage

Preserve the measurement wording exactly when relevant.

Do not reinterpret or convert SPL requirements unless explicitly asked.

## System Processing

Capture requirements for:

- system processor
- DSP
- system control software
- matrix processing
- measurement / alignment system
- manufacturer-specific control platform

Do not assume processing requirements based only on the PA manufacturer.

## System Engineer

Capture whether the rider requires:

- System Engineer
- PA Technician
- Manufacturer-certified technician
- Local system technician

Preserve whether the engineer is:

- artist supplied
- local production supplied
- venue supplied

## Preferences and Alternatives

Preserve distinctions between:

- required
- preferred
- acceptable
- alternative
- optional

Example:

`L-Acoustics preferred, d&b or Meyer acceptable`

must preserve:

- Preferred: L-Acoustics
- Acceptable: d&b, Meyer

Do not treat all manufacturers as equivalent.

## Conflicts

Flag conflicts between:

- PA specification
- venue technical specification
- stage plot
- production notes
- later rider revisions

Do not resolve conflicting PA requirements by assumption.
